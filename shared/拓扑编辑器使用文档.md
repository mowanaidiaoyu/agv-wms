# 拓扑编辑器使用文档

本文档面向第一次使用本平台拓扑编辑器的同学，目标是回答三个问题：

1. 每个对象工具是做什么的
2. 不同工具之间应该怎么连接
3. 怎样从零搭出一个可以校验、可以保存、可以用于仿真的完整拓扑

---

## 1. 先理解两个层次

当前拓扑编辑器是两层模型：

- 地面层
  - `通行路`
  - `障碍物`
  - `输送带`
- 功能层
  - `库位`
  - `站台`
  - `缓存位`
  - `入口`
  - `输送带闸口`
  - `交叉点`
  - `提升机`

可以把它理解成：

- 先铺地面
- 再把业务点放到地面上

如果只放功能点，不铺路，机器人没有路径。
如果只铺路，不放功能点，系统不知道货从哪里来、送到哪里去。

---

## 2. 对象工具逐个说明

### 2.1 操作类工具

#### `选择`

- 用途：选中已经画好的对象，查看或修改属性
- 典型操作：
  - 修改节点标签
  - 修改容量
  - 修改输送带方向
  - 查看当前对象属于哪个库区

#### `删除`

- 用途：删除你点中的对象
- 说明：
  - 删除功能节点，只删除节点本身
  - 删除地面格子，可能让该格子上的节点失效

---

### 2.2 地面层工具

#### `通行路`

- 用途：机器人正常行走的道路
- 使用方式：点击或拖拽连续刷入
- 适合放在：
  - 库位之间
  - 站台前
  - 闸口周围
  - 主干道和分支路

#### `障碍物`

- 用途：不可通行区域
- 使用方式：点击或拖拽连续刷入
- 作用：
  - 限制路径
  - 划分不可达区域
  - 模拟墙体、设备本体或禁止通行区

#### `输送带`

- 用途：带方向的自动运输介质
- 使用方式：
  1. 先刷出输送带格子
  2. 用 `选择` 点中输送带格子
  3. 在右侧属性中设置方向
- 注意：
  - 输送带不是普通道路
  - 输送带本体只表示“传送介质”
  - 机器人与输送带的交接要靠 `输送带闸口`

---

### 2.3 功能层工具

#### `库位`

- 用途：货物存放点
- 业务含义：货可以从这里被机器人取出
- 放置要求：应放在可达的通行路附近或直接落在道路格上

#### `站台`

- 用途：任务交付点、出库点、作业点
- 业务含义：任务最终送达的位置
- 放置要求：必须能通过道路或输送链路到达

#### `缓存位`

- 用途：临时等待和交接缓存
- 业务含义：用于排队、缓冲、等待释放资源
- 推荐位置：
  - 输送带出口附近
  - 站台前
  - 跨区交接点附近

#### `入口`

- 用途：任务或货物流进入系统的位置
- 业务含义：订单入口、入库入口、外部接入口
- 推荐位置：靠近主路或站台区

#### `输送带闸口`

- 用途：机器人区域与输送带之间的交接点
- 业务含义：上下带口、交接口
- 放置要求：
  - 必须紧邻输送带
  - 一般同时连接一段通行路

#### `交叉点`

- 用途：路径汇合、分流、转向点
- 业务含义：交通节点，不是货位
- 推荐位置：
  - 十字路口
  - 主通道和支路的连接处

#### `提升机`

- 用途：垂直提升或跨层转换设备
- 当前阶段作用：作为功能节点保留，供后续多层场景使用
- 单层示例中可先不使用

---

## 3. 工具之间到底怎么连接

这部分最重要。

### 3.1 连接规则总览

#### 规则 1：功能节点必须放在“可工作的地面”上

建议至少满足：

- `库位` 放在通行路上或紧贴通行路
- `站台` 放在通行路上
- `缓存位` 放在通行路上
- `入口` 放在通行路上
- `交叉点` 放在通行路上
- `提升机` 放在通行路上

#### 规则 2：输送带不能直接代替交接点

正确关系是：

`通行路 -> 输送带闸口 -> 输送带 -> 输送带闸口 -> 通行路`

不要直接把 `库位` 或 `站台` 当成输送带连接点。

#### 规则 3：缓存位通常放在“交接之后”或“站台之前”

典型关系是：

`输送带闸口 -> 缓存位 -> 站台`

或者：

`库位 -> 通行路 -> 缓存位 -> 站台`

#### 规则 4：完整链路至少要有“起点”和“终点”

最小闭环通常至少包含：

- 一个 `库位`
- 一个 `站台`

如果没有这两个，任务没有起点或终点。

## 4. 你可以直接照着搭的最小可运行拓扑

这是最推荐的入门拓扑。

### 4.1 目标

做出这样一条链：

`库位 -> 通行路 -> 输送带闸口 -> 输送带 -> 输送带闸口 -> 缓存位 -> 站台`

### 4.2 搭建顺序

#### 第一步：新建空拓扑

- 行数建议：`12`
- 列数建议：`20`
- 格子尺寸：默认即可

#### 第二步：先刷道路

用 `通行路` 画出一条连续主通道，例如：

- 左侧一列纵向通道
- 中间一段横向连接通道
- 右侧站台前通道

你可以简单理解成“先保证从左到右能走通”。

#### 第三步：放库位

在左侧道路附近放 `库位`：

- 至少放 `1` 个
- 推荐放 `2-3` 个，方便后续观察任务流转

#### 第四步：放交叉点

在主通道转弯或分叉处放 `交叉点`：

- 不是必须很多
- 但建议在关键转折处放上，便于表达路径结构

#### 第五步：刷输送带

在中间区域刷一段连续 `输送带`：

- 长度建议 `4-6` 格
- 方向统一，例如全部向右

#### 第六步：在输送带两端放闸口

在输送带入口一端放一个 `输送带闸口`

在输送带出口一端再放一个 `输送带闸口`

这样就形成：

`通行路 -> 闸口 -> 输送带 -> 闸口 -> 通行路`

#### 第七步：在出口侧放缓存位

在靠近输送带出口的一侧放 `缓存位`

作用是：

- 表示等待交接
- 后续方便做排队和缓冲

#### 第八步：放站台

在最右侧放 `站台`

要求：

- 能通过道路或缓存位到达
- 不要与障碍物隔开

#### 第九步：必要时放入口

如果你希望表达“订单或任务从某处进入系统”，可以在靠近站台或主通道的位置放一个 `入口`

不是最小闭环必须项，但推荐加一个，后续更完整。

#### 第十步：用选择工具检查属性

重点检查：

- 输送带方向是否正确
- 节点标签是否清楚
- 容量是否合理

#### 第十一步：校验拓扑

点击 `校验拓扑`

看是否存在：

- 缺少站台
- 缺少库位
- 闸口未邻接输送带
- 节点不可达

#### 第十二步：保存拓扑

校验通过后点击 `保存拓扑`

## 5. 一个更完整的仓储拓扑应该怎么组成

如果要做接近演示用的完整拓扑，建议包含 4 个区块：

### 5.1 CTU 区

组成：

- 多个 `库位`
- 一条或多条 `通行路`
- 若干 `交叉点`

作用：

- 表示 CTU 机器人作业区
- 货从这里被取出

### 5.2 输送线区

组成：

- 一段 `输送带`
- 两侧 `输送带闸口`
- `缓存位`

作用：

- 表示跨区交接
- 表示自动运输与等待机制

### 5.3 站台区

组成：

- 一个或多个 `站台`
- 靠近站台的 `通行路`
- 可选 `入口`

作用：

- 表示任务交付和出库作业

### 5.4 四向车区

组成：

- 多个 `库位`
- 一条或多条 `通行路`
- 若干 `交叉点`
- 与输送线相连的 `输送带闸口`

作用：

- 表示另一类作业区
- 与 CTU 区通过输送线协同

---

## 6. 推荐的搭建顺序

实际使用时，建议永远按下面顺序来：

1. 先确定网格大小
2. 先刷 `通行路`
3. 再刷 `输送带`
4. 再补 `障碍物`
5. 再放 `库位`
6. 再放 `站台`
7. 再放 `缓存位`
8. 再放 `闸口`
9. 再放 `交叉点`
10. 最后补 `入口 / 提升机`
11. 校验拓扑
12. 保存拓扑

不要一开始就先堆功能点，否则很容易出现“图上有东西，但实际上不连通”的问题。

---

## 7. 常见错误和对应修法

### 错误 1：只有库位，没有站台

- 问题：任务没有终点
- 修法：至少补一个 `站台`

### 错误 2：画了输送带，但没放闸口

- 问题：机器人无法和输送带交接
- 修法：在输送带两端放 `输送带闸口`

### 错误 3：闸口不贴着输送带

- 问题：校验会认为交接结构不成立
- 修法：把闸口放到紧邻输送带的格子

### 错误 4：站台或库位周围没有通行路

- 问题：节点不可达
- 修法：补一条通行路把它接入主通道

### 错误 5：全部都是路，没有业务节点

- 问题：只能表示交通，不能表示仓储流程
- 修法：至少加 `库位 + 站台`

### 错误 6：障碍物把主路径切断

- 问题：拓扑不连通
- 修法：检查是否误刷了障碍格

## 8. 建议你第一次就照着做的演示模板

如果你现在还不熟，最推荐你做下面这个结构：

### 左侧

- `3` 个库位
- `1` 条纵向主路
- `2-3` 个交叉点

### 中间

- `1` 条长度为 `5` 左右的输送带
- 输送带左右各 `1` 个闸口
- 出口附近 `1` 个缓存位

### 右侧

- `2` 个站台
- `1` 个入口
- 若干连接道路

这样你能同时学会：

- 路怎么铺
- 节点怎么放
- 输送带怎么接
- 缓存位怎么用
- 站台怎么连

## 9. 画完之后下一步做什么

画完拓扑后，标准流程是：

1. `校验拓扑`
2. `保存拓扑`
3. 进入 `场景配置台`
4. 给这个拓扑配置机器人、订单速率、策略参数
5. 进入 `仿真工作台` 启动仿真

也就是说：

- 拓扑解决“空间结构”
- 场景解决“运行参数”
- 仿真解决“任务执行过程”

如果你只记一句话，请记这个：

`先铺路，再放点；先连通，再分区；先校验，再保存。`

## 11. 给新手的最短操作版

如果你现在就想开始，直接按这个做：

1. 选 `通行路`，从左到右刷一条主路
2. 在左边放 `库位`
3. 在中间刷 `输送带`
4. 在输送带两端放 `闸口`
5. 在右边放 `缓存位`
6. 在最右边放 `站台`
7. 点 `选择` 检查输送带方向
8. 点 `校验拓扑`
9. 点 `保存拓扑`

做到这一步，你就已经搭出了一个最小可运行拓扑。

## 12. 多层结构应该怎么构建

当前版本的拓扑编辑器本质上还是一张二维网格，还没有真正的 `楼层 / floor / layer` 字段。

所以现在要做多层结构，推荐使用“平铺展开式多层建模”：

`一层区域 + 二层区域 + 三层区域` 都画在同一张大网格里，再用 `提升机` 表达不同楼层之间的连接关系。

### 12.1 推荐画法

假设你要画两层仓库，可以把网格横向分成两块：

`左半边 = 1F`

`右半边 = 2F`

例如：

- 第 0-19 列表示 `1F`
- 第 22-41 列表示 `2F`
- 中间留 1-2 列空白或障碍物作为视觉分隔

如果是三层，可以继续向右展开：

`1F -> 2F -> 3F`

也可以纵向展开：

`上方 = 1F`

`中间 = 2F`

`下方 = 3F`

### 12.2 每一层内部怎么画

每一层都按照普通单层拓扑来画：

1. 先刷 `通行路`
2. 再刷 `输送带`
3. 再放 `库位`
4. 再放 `站台`
5. 再放 `缓存位`
6. 再放 `闸口`
7. 再放 `交叉点`
8. 最后放 `提升机`

也就是说，不要把多层想成特殊图。

先把每一层当成一个完整的小仓库画出来，再考虑层与层之间怎么连接。

### 12.3 提升机怎么连接楼层

`提升机` 是多层结构里最关键的对象。

推荐规则：

- 每一层都放一个对应的 `提升机`
- 不同楼层的提升机使用相同前缀命名
- 提升机旁边必须有 `通行路`
- 提升机附近可以放 `缓存位`，表示等待换层

例如：

- `LIFT-A-1F`
- `LIFT-A-2F`

这两个节点表示同一台提升机在不同楼层的出入口。

如果有两台提升机，可以这样命名：

- `LIFT-A-1F`
- `LIFT-A-2F`
- `LIFT-B-1F`
- `LIFT-B-2F`

### 12.4 一个两层拓扑的推荐结构

第一层 `1F`：

- 入库口
- CTU 库位
- 通行路
- 提升机入口 `LIFT-A-1F`
- 提升机前缓存位

第二层 `2F`：

- 四向车库位
- 通行路
- 提升机出口 `LIFT-A-2F`
- 输送带
- 站台

推荐业务链路：

`1F入口 -> 1F通行路 -> LIFT-A-1F -> LIFT-A-2F -> 2F通行路 -> 2F库位/输送带/站台`

### 12.5 多层结构中缓存位怎么放

提升机附近一定建议放缓存位。

原因是：

- 设备可能需要等提升机
- 货物可能需要等待换层
- 后续仿真可以表达排队、拥堵、等待

推荐结构：

`通行路 -> 缓存位 -> 提升机 -> 缓存位 -> 通行路`

也就是提升机两边都留等待区。

### 12.6 多层结构中输送带怎么放

输送带仍然按单层逻辑处理。

如果输送带只在某一层内部运行：

`通行路 -> 闸口 -> 输送带 -> 闸口 -> 通行路`

如果你想表达“垂直输送线”，当前版本建议先用 `提升机` 表示，不要直接用输送带跨层。

### 12.7 多层拓扑的命名规范

建议所有节点标签都带楼层前缀。

推荐格式：

- `1F-STORAGE-A01`
- `1F-ENTRY-01`
- `1F-LIFT-A`
- `2F-LIFT-A`
- `2F-STATION-01`
- `2F-BUFFER-01`

这样后续看事件、任务、回放时不会混乱。

### 12.8 多层拓扑的区域划分

如果后续有区域编辑能力，建议这样划分：

- `1F-CTU区`
- `1F-入库区`
- `1F-提升机区`
- `2F-四向车区`
- `2F-输送线区`
- `2F-站台区`

如果当前页面暂时不能手动画区域，也可以先通过节点命名和画布布局来表达。

### 12.9 当前版本的限制

需要注意，当前版本还不是真正的三维多层拓扑。

也就是说：

- 系统不会自动知道 `LIFT-A-1F` 和 `LIFT-A-2F` 是同一台提升机
- 路径规划仍然主要基于二维网格
- 提升机更多是业务语义节点和后续扩展预留

当前阶段推荐先把多层结构“画清楚、命名清楚、关系清楚”。

等后续要做真正多层仿真时，再给拓扑模型增加：

- `floor`
- `liftGroupId`
- `verticalTravelTime`
- `floorTransferCost`
- `liftCapacity`

### 12.10 最短操作版

如果你现在就要画一个两层仓，直接按这个做：

1. 把左半边当作 `1F`
2. 把右半边当作 `2F`
3. 在 `1F` 画通行路、入口、库位
4. 在 `2F` 画通行路、库位、站台
5. 在 `1F` 放 `LIFT-A-1F`
6. 在 `2F` 放 `LIFT-A-2F`
7. 在两个提升机旁边都放 `缓存位`
8. 用道路把每层内部连通
9. 所有节点名称加上 `1F-` 或 `2F-`
10. 校验拓扑并保存

一句话记住：

`多层先平铺，层间靠提升机，节点名带楼层，提升机旁放缓存。`
## 13. 新版多层仿真用法

当前平台已经支持基础多层仿真：每一层是一张独立二维网格，通过“提升机资源”连接不同楼层。

### 13.1 多层拓扑由什么组成

- `楼层`：例如 `1F`、`2F`。拓扑编辑器画布上方可以切换当前楼层，也可以点击 `+ 楼层` 新增楼层。
- `同层对象`：每一层都要单独铺设通行路、障碍物、输送带、库位、站台、缓存位等对象。
- `提升机节点`：在需要跨层的位置，每一层放一个“提升机”节点。
- `提升机资源`：把不同楼层的提升机节点绑定到同一个 `lift` 资源，系统才会认为它们属于同一台提升机。
- `跨层路径`：机器人同层按上下左右移动，跨层只能通过同一提升机资源连接的提升机节点。

### 13.2 推荐搭建步骤

1. 在 `1F` 铺设道路、库位、站台或入口。
2. 在 `1F` 放置一个提升机节点，例如 `lift-1f`。
3. 点击 `+ 楼层` 新建 `2F`，切换到 `2F`。
4. 在 `2F` 铺设道路，并在对应位置放置提升机节点，例如 `lift-2f`。
5. 创建或编辑一个 `lift` 资源，让它的 `nodeIds` 包含 `lift-1f` 和 `lift-2f`。
6. 保存并校验拓扑。
7. 启动仿真后，在仿真工作台用楼层标签切换查看不同楼层。

### 13.4 当前版本限制

- 现在已经支持跨层寻路，但提升机还没有做复杂排队、容量时隙和故障恢复。
- 当前编辑器可以添加楼层和放置提升机节点，但资源绑定面板还需要后续增强；如果要立即测试跨层路径，可以先在拓扑 JSON 中补 `lift` 资源。
- 旧拓扑没有 `floor` 字段也可以继续使用，系统会默认当作 `1F`。

# 修改清单 —— 四向车库改为「CTU 式 4 层货架 + 巷道挖空」

- **日期**：2026-09-27
- **主题**：`/topology` 3D 拓扑编辑器，四向车库（shuttle 区域）不再只是一块扁平「面」，而是像 CTU 库一样直接铺出 4 层货架；画在区域内的 road 巷道（2×2 全格）会把对应槽位挖空，供四向车上下左右通行。全部集中在前端渲染，**后端与仿真逻辑零改动**。

---

## 背景 / 用户诉求

上一版（`修改清单-四向车库巷道可见性修复`）把四向车库渲染成「薄底板 + 线框」，货架只由**逐个放置的 storage 库位节点**贡献。用户刷新后拉一个「四向车平库」区域，看到的仍是一个面，没有 4 层、没有货架。

用户的预期：「四向车库**类似于目前的 CTU 库**（区域本身就是一个多层货架），不同点在于可以**修改某片区域把它变成巷道**，方便四向车在其中上下左右移动。」

## 改动（全部在 `web/frontend/src/lib/topology3d.ts`）

### 1. shuttle 区域本身铺出 4 层货架（原来是「薄底板 + 线框」）

`zone.type === 'shuttle'` 分支在保留薄底板 + 线框边界的同时，按 **2×2 槽位**遍历整个区域，为每个非巷道槽位发一个 `rack`（复用 CTU 的货架渲染 `RackView`）：

```ts
for (let r = zone.y; r + 1 < zone.y + zone.height; r += 2) {
  for (let c = zone.x; c + 1 < zone.x + zone.width; c += 2) {
    // 槽位 4 格全为 road 视为巷道，挖空不铺货架
    let aisle = true
    for (let dr = 0; dr < 2; dr += 1)
      for (let dc = 0; dc < 2; dc += 1)
        if (cellAt.get(`${floor}:${r + dr}:${c + dc}`)?.type !== 'road') aisle = false
    if (aisle) continue
    items.push({ kind: 'rack', /* 2×2、4 层、层高 1.4、橙色 */ ... })
  }
}
```

- `levels: ZONE_LEVELS.shuttle`（4）、`slotSize: 2`、`levelHeight: ZONE_LEVEL_HEIGHT.shuttle`（1.4）、`color: zonePadColor.shuttle`（橙）。
- 每槽位 = 4 角立柱 + 4 层层板，与 CTU 同一视觉语言。
- 槽位中心坐标与 storage 2×2 库位同口径（`worldX(c)+CELL/2`、`worldZ(r)-CELL/2`）。
- 每个槽位货架的 `entity` 仍是 `{ kind: 'zone', id: zone.id }`，点任一槽位即选中整个区域。

### 2. 巷道挖空规则

- 某 2×2 槽位 **4 格全为 road** → 判定为巷道，跳过不铺货架（road 格本身仍渲染为蓝色通行路，见上一版修复）。
- 仅个别 road 格（如 storage 库位落位时自动铺的底格，只有 1 格 road）→ **不挖空**，货架保留，避免放库位反而把自己挖成巷道。

### 3. storage 2×2 库位：由「独立 4 层货架」改为「小标记」

上一版给每个 2×2 库位单独画了一个 4 层货架；现在货架由**所在 shuttle 区域统一铺出**，库位节点改回一个小而可点选的标记（`box`，1.4×0.5×1.4，灰蓝 `#5b6b85`，位于槽位中心 y+0.4），用于查看/选中/删除，不再重复画货架。1×1 库位（CTU）不变。

## 验证结果

- `npx tsc -b` ✅
- `npx vitest run` ✅ 12/12 passed（topology.test 10 + TopologyPage + App）

## 交互 / 行为变化

- 拉一个「四向车库」区域 → **立即出现整片 4 层货架**（不再只是面），像 CTU 库。
- 在区域内用 road 铺 **2 宽巷道**（槽位 4 格全 road）→ 对应槽位被挖空，露出蓝色通行路，四向车在其中上下左右移动。
- 放「库位」→ 槽位仍保留货架，库位以小标记显示在槽位底部，可点选。
- 单格 road 不挖空（避免误伤库位底格）。

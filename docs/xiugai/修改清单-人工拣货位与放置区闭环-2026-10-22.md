# 修改清单：人工拣货位与放置区完整闭环

- 日期：2026-10-22
- 主题：重写 CTU 交付后的阶段机，新增「放置区（drop_zone）」区域类型，把现有「人工拣货台」更名为「人工拣货位」，形成 出库 → 下层输送 → 升降 → 上层输送 → 人工拣货 → 放置 → 回程 → 取回 → 回库 的完整闭环。

---

## 背景

原实现中，CTU 交付到输送线出入口（`delivery_to_port`）后只有一个合并的 `conveyor_transfer` 计时阶段，随后直接进入 `picking`，拣完经 `conveyor_return` 回到出入口取回、回库。存在三个缺口：

1. 输送线「下层转运 → 升降移栽 → 上层输送」三段物理过程被压成一个计时，动画与阶段对不上；
2. 拣出的货物没有去处——没有「放置区」概念，货物凭空消失后再随空箱回库；
3. 区域类型只有 `pick_station`（显示名「人工拣货台」），无法在拓扑编辑器里画放置区。

> 用户需求核心：新增「人工拣货位」「放置区」两个可设置区域；重写 CTU 交付后的阶段机为 10 步完整流程；无 `pick_station` 时保持原行为（交付即完成）。

---

## 新阶段机流程

拓扑有 `pick_station` 时，CTU 任务按以下阶段链推进（全部计时阶段由统一的 `remainingStageTicks` 驱动）：

| # | 阶段 | 中文标签 | 计时配置 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | `delivery_to_port` | 输送线交付 | 路径移动 | CTU 到出入口后播放与取货对称的交付动作（升降对位 → 伸叉送箱 → 箱入输送线，3 tick） |
| 2 | `conveyor_to_lift` | 下层输送转运 | `conveyorTransferTicks` | 下层输送线把货箱运送到升降移栽机 |
| 3 | `lift_to_upper` | 升降移栽 | `liftTicks`（新增） | 升降移栽机把货箱抬到输送线上方 |
| 4 | `conveyor_to_pick` | 上层输送至拣货位 | `conveyorTransferTicks` | 上层输送线把货箱运到人工拣货位 |
| 5 | `picking` | 人工拣货 | `pickTicks` | 货箱停在拣货位，自动计时；`complete-picking` 接口可跳过 |
| 6 | `place_goods` | 拣货放置 | `placeTicks`（新增） | 拣出的货物放到放置区；结束时记录 `placedGoods`（lines 快照）。拓扑没有 `drop_zone` 时跳过此阶段 |
| 7 | `conveyor_return` | 输送线回程 | `conveyorTransferTicks` | 空货箱沿上层输送线运回出入口 |
| 8 | `pickup_from_port` | 出入口取回 | 路径移动 | CTU 到出入口取回货箱 |
| 9 | `return_to_storage` | 回库 | 路径移动 | 按订单行把货箱送回原库位、原层 |
| 10 | `completed` | 已完成 | — | 库存恢复原 `nodeId` + `layer`，`qty` 不变 |

拓扑没有 `pick_station` 时：`delivery_to_port`（含交付动作）结束后直接 `completed`，与原行为一致。

放置区选择逻辑：`_drop_zone_for` 仿照 `_pick_station_for`，按与拣货位入口格的曼哈顿距离取最近的 `drop_zone`；入口格与 port 同口径（区域底边中点）。

---

## 配置项（`web/backend/app/services/simulation_config.py`）

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `conveyorTransferTicks` | 6 | 每段输送线转运计时（下层→升降机 / 上层→拣货位 / 上层→出入口回程） |
| `liftTicks` | **新增 3** | 升降移栽机把货箱从下层抬到上层 |
| `pickTicks` | 6 | 人工拣货计时；`complete-picking` 可提前结束 |
| `placeTicks` | **新增 3** | 拣出货物放到放置区的计时；无 `drop_zone` 时跳过 |

## 后端改动

### `web/backend/app/services/simulation_config.py`

- 新增 `liftTicks: 3`、`placeTicks: 3`，补注释；`conveyorTransferTicks` 注释改为「每段输送转运」口径。

### `web/backend/app/services/pathfinding.py`

- 新增 `drop_zone_zones()` 与 `drop_zone_entry_cell()`（入口格 = 区域底边中点，与 `port_entry_cell` 同口径）。
- `pick_station_entry_cell` 注释同步改为「拣货位」。

### `web/backend/app/services/simulation.py`

- `_build_task`：移除 `remainingConveyorTicks` / `remainingPickTicks`，改为统一 `remainingStageTicks`；新增 `dropZoneZoneId` / `dropZoneCellId` / `placedGoods` 字段。
- 新增 `_advance_ctu_delivery_action`：交付到出入口时用与取货对称的三段动作（`lifting → extending → stowing`，`handlingAction.type = "deliver"`）把货箱送上输送线，动作结束后才进入转运或完成任务。
- 新增 `_enter_timed_stage`：所有计时阶段的通用入口（写 `phase`/`remainingStageTicks`/机器人 waiting/事件）。
- `_start_conveyor_transfer` 改名重写为 `_start_conveyor_to_lift`（阶段 `conveyor_to_lift`），记录 `transitGoods` / `deliveredGoods` / 拣货位信息后 `_step_off_port`。
- 新增 `_advance_timed_stage`：计时归零后的阶段链接续（conveyor_to_lift → lift_to_upper → conveyor_to_pick → picking → place_goods → conveyor_return → pickup_from_port）。
- 新增 `_drop_zone_for`：按与拣货位入口格的曼哈顿距离取最近 `drop_zone`。
- `_finish_picking` 重写：有 `drop_zone` 时记录 `dropZoneZoneId`/`dropZoneCellId` 并进入 `place_goods`，否则直接 `_start_conveyor_return`；`place_goods` 结束时记录 `placedGoods`（lines 快照）。
- `_start_conveyor_return`：统一回程计时入口，重置 `returnLineIndex`。
- `_advance_robot_phase`：`delivery_to_port` 委托给交付动作；`conveyor_to_lift / lift_to_upper / conveyor_to_pick / picking / place_goods / conveyor_return` 六个阶段共用一个 `remainingStageTicks` 计时分支。
- `_complete_task`：`remainingPickTicks` → `remainingStageTicks`。
- `_phase_label` 新增：`conveyor_to_lift`「下层输送转运」、`lift_to_upper`「升降移栽」、`conveyor_to_pick`「上层输送至拣货位」、`place_goods`「拣货放置」；其余沿用。
- 已确认 `drop_zone` 不会被当作 port/ctu/shuttle 处理：交付点、库存生成（`goods.py`）、四向车路径等全部按 `zone.type` 精确过滤，`drop_zone` 不产生库位节点、不参与寻路占用。

### 接口

- `POST /api/v1/simulations/{run_id}/tasks/{task_id}/complete-picking` 行为不变（仅 `picking` 阶段可调用），跳过后现在进入 `place_goods`（有放置区）或 `conveyor_return`（无放置区）。

## 追加修复（同日第二轮：保存失败 / 首车货箱不可见 / 上层漂移）

用户反馈三个问题：①添加放置区后拓扑无法保存；②Demo 6.6 实测第一辆 CTU 交付时观察不到下层输送线上的货箱；③货箱经升降移栽机到上层后直线「飘逸」到拣货区。

### 根因与修复

1. **放置区无法保存**（`web/backend/app/schemas.py`）
   - 根因：`ZoneType = Literal[...]` 缺少 `"drop_zone"`，前端提交含放置区的拓扑被 pydantic 422 整体拒绝（连同同一次编辑里的人工拣货位也一起没保存，导致 Demo 6.6 保存后没有任何新区域）。
   - 修复：`ZoneType` 补 `"drop_zone"`。已通过 API 把 Demo 6.6 连同新增的 4 个区域（`zone-pick-1`/`zone-drop-1` 对应第一条输送线，`zone-pick-2`/`zone-drop-2` 对应第二条线，均放在输送线上方一格、入口格贴近上层带面）保存成功，用户可再在编辑器里自行调整位置。

2. **上层「飘逸」到拣货区**（`web/frontend/src/components/topology/Simulation3DScene.tsx`）
   - 根因：出站路径为 `[...liftRoute, stationPoint]`——升降机顶部到拣货台入口是一条全长直线，拣货台不沿上层输送带方向时货箱斜穿空中；回程路径 `[stationPoint, ...route 反向 @upperY, portPoint]` 的第一段同样是直线漂移。
   - 修复：`conveyorPath` 现在返回 `{ points, beltCells }`（途经输送格），出站改为「升降机顶部 → 沿上层带面（与下层同一批格子、抬到上层带面高度）反向行走到距拣货台最近的输送格 → ≤1 格短跳上拣货台」；回程改为「拣货台 → 最近输送格 → 沿上层带面走到出入口端 → 出入口上方」。拣货台距带面 >3 格时放弃站台点（停在上层带面末端），彻底杜绝跨场直线。
   - 回程货箱 `skipRise` 改为 `true`（货箱本来就在拣货台上，不再播放从带下升起的动画）。

3. **货箱动画与阶段时长不匹配导致瞬移**（同文件）
   - 出站路径（下层输送 + 升降 + 上层反向 + 短跳）约 19.5 格，原速度 1.2 格/秒需 16.3s，超过后端 `conveyor_to_lift → picking` 合计约 12.6s，阶段切到 `conveyor_return` 时货箱会从半路瞬移回拣货台。
   - 修复：`DELIVERY_SPEED` 1.2 → 1.8（与机器人 1 格/0.6s 节奏匹配），出站动画约 11.6s，可在回程阶段开始前走完。

4. **首车货箱可见性排查结论**（无代码改动，数据/环境问题）
   - 运行时证据（启动仿真逐 tick 采样）：后端在交付动作 3 tick 内正确记录 `deliveredGoods=3`，任务随即 `completed`；前端在 `delivery_to_port && atPort` 与 `completed` 两个窗口都能生成货箱，浏览器实测（带拣货位完整流程）货箱全程可见。
   - 用户此前「第一辆 CTU 看不到货箱」的直接原因：当时保存失败导致拓扑里没有任何拣货位，任务在交付后立即 `completed`，货箱动画（升起+沿带面走远+淡出）在 CTU 停靠点附近只停留 1-2 秒即被输送线带走，观察窗口极短；且旧观察发生在 schemas 修复热重载前的环境。现在完整拣货流程下货箱在输送线上停留数十秒，问题不再出现。

### 验证结果（追加）

- 浏览器实测（Demo 6.6 + 4 个新区域）：货箱从下层带面升起 → 右行 → 升降机垂直抬升 → 沿上层带面左行到拣货位停住 → 拣货后沿上层带面回到出入口上方 → CTU 取回，全程贴带面移动，无斜穿/瞬移/数量异常，控制台无运行时错误。

## 风险与后续

1. 出站动画共用一条 outbound 路径按时间播放；本轮已把 `DELIVERY_SPEED` 提到 1.8 使其在阶段链内走完，但若输送线路由更长（跨多块 2×2），仍可能出现货箱在拣货位提前停住等待阶段推进的情况，未做逐段与阶段 tick 严格对齐。
2. 演示场景默认 `durationTicks = 90`，闭环链路变长后（交付 3 tick + 输送 15 tick + 拣货 6 tick + 放置 3 tick + 回程 6 tick + 取回/回库路径），单趟任务耗时明显增加；想看完整体流程需把运行时长调大（建议 150-200）。
3. 多个任务共享同一条输送线时，`dropGoods` 放置货物按任务各自渲染，未做放置区容量/占位冲突检查（与拣货位行为一致）。
4. 本轮为 Demo 6.6 补的 4 个区域位置（拣货位/放置区各两个，分别贴近两条输送线上方）是按「入口格距上层带面 ≤1 格」原则通过 API 预置的，用户可在拓扑编辑器中拖动调整；若挪到离带面超过 3 格的位置，货箱将停在上层带面末端而不再跳上拣货台（防漂移兜底）。

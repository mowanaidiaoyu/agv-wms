# 服务器部署说明（AGV 仿真平台 · Windows Server）

> 适用：把本机已跑通的 WMS 项目搬到 **Windows 服务器**上，让团队成员通过浏览器访问。
> 本机开发启动见同目录 `启动方法.md`；GitHub 协作见 `GitHub上传协作指南.md`。

---

## 1. 架构与端口

| 组件 | 技术 | 端口 | 说明 |
| --- | --- | --- | --- |
| 后端 | FastAPI + SQLite | 8000 | REST `/api/v1/*` + WebSocket `/ws/simulation/{run_id}` |
| 前端 | React + Vite 构建产物 | 见方案 | `frontend/dist/` 纯静态文件 |
| 数据库 | SQLite 单文件 | — | `backend/app_data/agv_platform.db`，首次启动自动建表 |

- 后端首次启动会从 `web/data/` 自动播种示例拓扑 / 场景（`seeder.py`）。
- 仿真实时刷新走 **WebSocket**（不是轮询）。

---

## 2. 环境要求（Windows Server 上装一次）

- **Python 3.12**：python.org 装 64 位版，勾选「Add python.exe to PATH」。
- **Node.js ≥ 20.19（建议 22 LTS）+ npm**：nodejs.org 装 LTS 版。
- 服务器**防火墙放行 8000**（若用 8000 对外）——见第 5 节。

---

## 3. 数据说明（重要）

运行时**只需要** `web/data/` 下这些小文件（都在 git 里）：

- `sample_topology.json`、`sample_scenario.json`（启动自动播种）
- `sku_catalog.json`（CTU 按商品属性取货用的 SKU 目录）

`WMS\data\` 里约 187MB 的 `.dxf/.dwg/.xlsx` 源数据**只在一次性导入 / 抽取时用**，服务器运行时不需要（别往服务器传这些大文件）。

---

## 4. 部署方案（三选一）

### 方案 A（推荐）：后端直接托管前端，单端口 8000，无需 IIS/Nginx

前端构建产物让 FastAPI 一起托管，前后端同源、无跨域、无反向代理，只有一个 8000 端口，最简单。

**4.A.1 取代码 + 装依赖**

```powershell
git clone git@github.com:mowanaidiaoyu/agv-wms.git   # 或直接把代码打包上传
cd agv-wms
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
cd frontend
npm install
npm run build          # 产物在 frontend\dist\
```

**4.A.2 两处代码改动（部署前一次性，改完重新 build）**

① `frontend/src/lib/api.ts` 第 14–15 行，改成相对地址：

```ts
const API_BASE = '/api/v1'
const WS_BASE = `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}/ws`
```

② `backend/app/main.py` 末尾加静态托管 + SPA 回退（已有 dist 才启用，不影响本机开发）：

```python
from pathlib import Path
from fastapi.staticfiles import StaticFiles
from fastapi.responses import FileResponse

DIST_DIR = Path(__file__).resolve().parents[2] / "frontend" / "dist"
if (DIST_DIR / "index.html").exists():
    app.mount("/assets", StaticFiles(directory=DIST_DIR / "assets"), name="assets")

    @app.get("/{full_path:path}", include_in_schema=False)
    async def serve_spa(full_path: str):
        candidate = DIST_DIR / full_path
        if candidate.is_file():
            return FileResponse(candidate)
        return FileResponse(DIST_DIR / "index.html")
```

改完 ① 后再 `cd frontend && npm run build`。

**4.A.3 启动后端（对外监听）**

```powershell
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

浏览器访问 `http://服务器IP:8000/` 即打开前端。生产环境**不要加 `--reload`**、**保持单进程**（仿真 WebSocket 广播是进程内单例，别开多 worker）。

**4.A.4 让后端开机自启（可选）**：用 **NSSM** 把上面的 uvicorn 命令注册成 Windows 服务。

```powershell
nssm install agv-wms-backend "C:\...\agv-wms\.venv\Scripts\python.exe" "-m uvicorn app.main:app --host 0.0.0.0 --port 8000"
nssm set agv-wms-backend AppDirectory "C:\...\agv-wms\backend"
nssm start agv-wms-backend
```

---

### 方案 B：IIS 托管前端 + 反代后端（服务器已有 IIS 时）

1. 装 **URL Rewrite** 和 **Application Request Routing (ARR)** 两个 IIS 扩展（微软官方下载）。
2. IIS 新建网站，物理路径指向 `frontend\dist\`，绑定 80 端口。
3. 在网站级建反向代理规则：`/api/v1/*` → `http://127.0.0.1:8000/api/v1/*`，`/ws/*` → `http://127.0.0.1:8000/ws/*`。
4. WebSocket：IIS 8+ 原生支持 WS 升级，ARR 里确保开启 WebSocket（`web.config` 加 `webSocket enabled="true"`）。
5. `api.ts` 改相对地址（同方案 A 的 ①），重新 build；后端绑 `127.0.0.1:8000`。

---

### 方案 C：直连（内网临时演示，最省事）

1. 后端对外监听：`uvicorn app.main:app --host 0.0.0.0 --port 8000`。
2. `api.ts` 写死服务器 IP：
   ```ts
   const API_BASE = 'http://服务器IP:8000/api/v1'
   const WS_BASE = 'ws://服务器IP:8000/ws'
   ```
3. `backend/app/main.py` 的 `allow_origins` 加前端源（如 `http://服务器IP:5173`）。
4. 前端 `npm run build` 后随便起个静态服务（如 `npx serve -s dist`），或直接 IIS 静态站点。

> 方案 C 有跨域、要把 8000 暴露到公网，只建议内网临时用；长期用选 A 或 B。

---

## 5. Windows 防火墙放行 8000（方案 A/C 需要）

管理员 PowerShell：

```powershell
netsh advfirewall firewall add rule name="AGV-WMS-8000" dir=in action=allow protocol=TCP localport=8000
```

## 8. 常见坑

1. **页面能开但没数据**：`api.ts` 还写死 `127.0.0.1:8000`，没改成相对地址 / 服务器 IP，或改完没重新 `npm run build`。
2. **别人访问不到**：后端用了 `--host 127.0.0.1`（只本机）；要对外必须 `--host 0.0.0.0`，并放行防火墙端口。
3. **仿真画面不实时 / 卡住**：反代没配 WebSocket 升级（方案 B），或超时太短；方案 A 无此问题。
4. **开了多进程 / 多 worker**：仿真 WebSocket 广播是进程内单例，必须单进程，否则收不到消息。
5. **SQLite 权限**：`backend/app_data/` 目录需对运行后端的用户可写。
6. **PowerShell 报「禁止运行脚本」**：`powershell -ExecutionPolicy Bypass -File .\xxx.ps1`。
7. **8000 被占用**：先 `netstat -ano | findstr :8000` 找到 PID，再 taskkill 或换端口。

## 附：若以后要换 Linux 服务器

步骤同 Windows，差异点：用 `python3.12 -m venv`、`source .venv/bin/activate`、`python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`；反代用 Nginx（`/api/v1/` 和 `/ws/` 反代到后端，`/ws/` 加 `Upgrade`/`Connection` 头 + `proxy_read_timeout 3600s`）；进程托管用 systemd。其余（api.ts 相对地址、单进程、数据文件）完全一致。

# 服务器部署说明（AGV 仿真平台）

> 适用：把本机已跑通的 WMS 项目搬到 Linux 服务器上，让团队成员通过浏览器访问。
> 本机开发启动见同目录 `启动方法.md`；GitHub 协作见 `GitHub上传协作指南.md`。

---

## 1. 架构与端口

| 组件 | 技术 | 端口 | 说明 |
| --- | --- | --- | --- |
| 后端 | FastAPI + SQLite | 8000 | REST `/api/v1/*` + WebSocket `/ws/simulation/{run_id}` |
| 前端 | React + Vite 构建产物 | 由 Nginx 提供 | `frontend/dist/` 纯静态文件 |
| 数据库 | SQLite 单文件 | — | `backend/app_data/agv_platform.db`，首次启动自动建表 |

- 后端首次启动会从 `web/data/` 自动播种示例拓扑 / 场景（`seeder.py`）。
- 仿真实时刷新走 **WebSocket**（不是轮询），反向代理必须支持 WebSocket 升级。

---

## 2. 环境要求

- **Python 3.12**（后端依赖见 `backend/requirements.txt`）。
- **Node.js ≥ 20.19（建议 22 LTS）+ npm**（前端构建）。
- （生产建议）**Nginx** 做静态文件 + 反向代理；可选 systemd 托管后端进程。

---

## 3. 数据说明（重要）

运行时**只需要** `web/data/` 下这些小文件（都在 git 里）：

- `sample_topology.json`、`sample_scenario.json`（启动自动播种）
- `sku_catalog.json`（CTU 按商品属性取货用的 SKU 目录）

`WMS\data\` 里约 187MB 的 `.dxf/.dwg/.xlsx` 源数据**只在一次性导入 / 抽取时用**，服务器运行时不需要（别往服务器传这些大文件）。

## 4. 部署步骤（Linux）

### 4.1 取代码

```bash
git clone git@github.com:mowanaidiaoyu/agv-wms.git
cd agv-wms
```

> 国内服务器若 SSH 不通，先在服务器上配置 SSH 走 443（见 `GitHub上传协作指南.md` 第 1 节），或直接把本机代码打包上传。

### 4.2 后端依赖

```bash
cd backend
python3.12 -m venv ../.venv
source ../.venv/bin/activate
pip install -r requirements.txt
```

### 4.3 前端构建

```bash
cd ../frontend
npm install
npm run build        # 产物在 frontend/dist/
```

> 构建内含 `tsc -b` 类型检查，必须通过才会产出 dist。

### 4.4 启动后端（先做 4.5 的关键改动再启动）

```bash
cd ../backend
source ../.venv/bin/activate
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

- 生产环境**不要加 `--reload`**。
- 后端**只跑 1 个 worker**（默认就是 1 个）：仿真 WebSocket 广播是进程内单例（`runtime.py` 的 `simulation_service`），多 worker 会互相收不到消息。**不要用 `--workers > 1` 或 gunicorn 多进程。**

### 4.5 ⚠️ 关键：前端里写死了后端地址，远程访问必须先改

`frontend/src/lib/api.ts` 第 14–15 行写死了 `127.0.0.1:8000`：

```ts
const API_BASE = 'http://127.0.0.1:8000/api/v1'
const WS_BASE = 'ws://127.0.0.1:8000/ws'
```

改成**相对地址 / 当前域名**（同源反代方案，推荐）：

```ts
const API_BASE = '/api/v1'
const WS_BASE = `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}/ws`
```

改完**重新 `npm run build`**。

> 不改成同源，浏览器访问的是 `http://你的服务器`，但前端仍会去连 `127.0.0.1:8000`（指向用户自己的电脑），页面必然加载不出数据。

### 4.6 Nginx 反向代理（同源方案）

`/etc/nginx/conf.d/agv-wms.conf`：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    root /opt/agv-wms/frontend/dist;
    index index.html;

    # 前端 SPA：路由回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # REST 反代到后端
    location /api/v1/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # WebSocket 反代（仿真实时刷新）
    location /ws/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;   # 长连接，别按默认 60s 断
    }
}
```

```bash
nginx -t && systemctl reload nginx
```

> 要上 HTTPS：用 certbot 给这个 server 加证书即可（前端 WS 会自动切 `wss`）。

### 4.7 systemd 托管后端（可选，推荐）

`/etc/systemd/system/agv-wms-backend.service`：

```ini
[Unit]
Description=AGV WMS backend
After=network.target

[Service]
WorkingDirectory=/opt/agv-wms/backend
ExecStart=/opt/agv-wms/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now agv-wms-backend
```

- 导入「666」拓扑到服务器后端（先确保后端已启动）：
  ```bash
  cd /opt/agv-wms
  .venv/bin/python scripts/import_topology.py docs/topologies/666.json
  ```
- 重新生成 SKU 目录（**只有**当你带了源 xlsx 且要重抽时才需要，运行时不需要）：
  ```bash
  .venv/bin/python backend/scripts/extract_sku_catalog.py
  ```

## 7. 常见坑

1. **页面能开但没数据**：`api.ts` 还写死 `127.0.0.1:8000`，没做 4.5 改动，或改完没重新 `npm run build`。
2. **仿真画面不实时 / 卡住**：Nginx 没配 WebSocket 升级（`location /ws/`），或 `proxy_read_timeout` 太短。
3. **开了多 worker 导致 WebSocket 收不到**：后端必须单进程单 worker。
4. **CORS 报错**：用同源反代（4.5+4.6）不会有 CORS；若坚持前端直连后端跨域，需在后端 `app/main.py` 的 `allow_origins` 里加服务器前端域名。
5. **SQLite 权限**：`backend/app_data/` 目录需对运行后端的用户可写，否则建库失败。
